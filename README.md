# 《剑来》知识图谱项目

本仓库维护《剑来》长篇文本的结构化数据管道、知识图谱构建逻辑、质量规则、设计文档和可审查的 JSON 数据样例。

配套微信小程序位于独立公开仓库 [`badDevBuild/jianlai`](https://github.com/badDevBuild/jianlai)。两个仓库独立发布：本仓库负责数据生产与项目知识，小程序仓库负责用户界面和客户端运行时。

## 主要内容

- `data/build/`：规范化后的构建数据和中间产物。
- `data/dist/`：供客户端消费的发布数据。
- `scripts/`：数据补全、校验、同步和构建脚本。
- `docs/`：数据管道、架构、产品研究、运维和故障排查文档。
- `openspec/`：能力规格、变更提案及实现记录。

文档入口见 [`docs/README.md`](docs/README.md)，项目约定与常用命令见 [`CLAUDE.md`](CLAUDE.md)。

## 数据流程

```text
原始章节/抽取结果
        ↓
实体合并与名称规范化
        ↓
人物、势力、地点、法宝、关系、语录等构建数据
        ↓
一致性检查与索引生成
        ↓
data/dist 发布数据
        ↓
微信小程序与其他客户端
```

## 安全与发布边界

- 不提交私钥、证书包、Token、生产 `.env` 或真实运维凭证。
- 大批生成图片、构建缓存和本机 Agent 技能不进入 Git。
- JSON 样例和发布数据可以进入仓库，但生成规则与来源应可追溯。
- 生产发布与 GitHub 上传是两件事；进入仓库不代表已经部署。

部署流程使用脱敏文档：[`docs/deploy.md`](docs/deploy.md)。

## 仓库关系

| 仓库 | 用途 | 可见性 |
|---|---|---|
| `jianlai-knowledge-graph` | 数据管道、知识图谱、说明文档、JSON 样例 | 私有 |
| `jianlai` | Taro 微信小程序源码和设计资源 | 公开 |

不要从父仓库强制推送到小程序仓库；两者拥有独立 Git 历史。
