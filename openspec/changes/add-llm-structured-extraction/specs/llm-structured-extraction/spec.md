## ADDED Requirements

### Requirement: LLM Extractor Mode
The system SHALL provide an LLM extractor mode for the generic novel knowledge graph pipeline while retaining the existing heuristic mode.

#### Scenario: Operator selects LLM extraction
- **GIVEN** a novel input file and output project path
- **WHEN** the operator runs the pipeline with extractor mode `llm`
- **THEN** the pipeline MUST call an injected or configured LLM provider for chapter facts
- **AND** the generated manifest MUST identify the extractor mode as LLM-based

#### Scenario: Offline baseline remains available
- **GIVEN** no LLM endpoint is available
- **WHEN** the operator runs the pipeline with extractor mode `heuristic`
- **THEN** the pipeline MUST retain the existing deterministic heuristic behavior

### Requirement: Evidence-Gated Fact Acceptance
The system SHALL accept LLM-produced facts into canonical records only when their supporting quote is present in the source chapter.

#### Scenario: Quote is found in chapter text
- **GIVEN** the LLM returns an entity, relationship, or event with a supporting quote
- **WHEN** the quote matches the chapter text after whitespace normalization
- **THEN** the fact MAY be normalized into canonical JSONL
- **AND** the canonical record MUST reference an evidence record with the chapter ID and quote

#### Scenario: Quote is not found
- **GIVEN** the LLM returns a fact with a supporting quote
- **WHEN** the quote cannot be found in the chapter text
- **THEN** the fact MUST NOT be written to canonical entity, relationship, event, or timeline files
- **AND** the fact MUST be written to the review queue with reason `evidence_not_found`

### Requirement: Relationship Endpoint Resolution
The system SHALL only accept LLM relationships whose source and target names resolve to accepted entities.

#### Scenario: Relationship endpoints resolve
- **GIVEN** the LLM returns a relationship between two entity names
- **WHEN** both names resolve to accepted entities in the current project
- **THEN** the relationship MUST reference the stable source and target entity IDs

#### Scenario: Relationship endpoint is missing
- **GIVEN** the LLM returns a relationship whose source or target entity is not accepted
- **WHEN** the extractor validates the relationship
- **THEN** the relationship MUST be rejected into the review queue with reason `missing_endpoint`

### Requirement: Review Queue Traceability
The system SHALL persist rejected LLM facts in a review queue that preserves chapter context and rejection reason.

#### Scenario: Rejected facts exist
- **GIVEN** one or more LLM facts fail validation
- **WHEN** the pipeline finishes
- **THEN** `source/extraction/review_queue.jsonl` MUST contain one JSON object per rejected fact
- **AND** each review row MUST include chapter ID, fact type, reason, and original fact payload

### Requirement: Per-Chapter LLM Fact Cache
The system SHALL persist and reuse per-chapter LLM responses so long novel runs can be resumed without re-calling completed chapters.

#### Scenario: Cached facts exist
- **GIVEN** `source/extraction/chapter_facts/<chapter_id>.json` already contains a raw LLM response for a chapter
- **WHEN** the LLM pipeline is rerun for that project
- **THEN** the extractor MUST reuse the cached raw facts for that chapter
- **AND** it MUST rebuild canonical records from the cached facts without calling the provider for that chapter

### Requirement: Quality Visibility
The system SHALL expose LLM extraction quality signals in status and inspection outputs.

#### Scenario: Pipeline status is written
- **GIVEN** the LLM extractor finishes
- **WHEN** the pipeline writes `pipeline_status.json`
- **THEN** status MUST include accepted fact counts and rejected fact counts

#### Scenario: Quality report is generated
- **GIVEN** a project was generated by the LLM extractor
- **WHEN** the operator generates the quality report
- **THEN** the report MUST surface extractor mode and review queue count

### Requirement: Independent Evidence Validation
The system SHALL independently validate canonical evidence quotes against persisted chapter text.

#### Scenario: Canonical evidence quote is missing from chapter text
- **GIVEN** a canonical evidence record references a valid chapter
- **WHEN** the evidence quote cannot be found in that chapter's persisted text after whitespace normalization
- **THEN** project validation MUST fail
- **AND** the validation error MUST identify the evidence ID and chapter ID

#### Scenario: Entity evidence reference is missing
- **GIVEN** a canonical entity record lists an evidence ID
- **WHEN** that evidence ID is absent from `source/canonical/evidence.jsonl`
- **THEN** project validation MUST fail
